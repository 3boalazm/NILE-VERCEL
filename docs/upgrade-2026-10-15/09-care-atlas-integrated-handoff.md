## 3. المراجعة البصرية والإصلاحات أثناء الدمج

لم أنسب نجاح اختبارات النموذج إلى تطبيق React. شُغّلت نسخة Next وفُحصت لقطاتها، ثم أُعيد البناء والتحقق بعد التصحيح:

1. وراثة لون النص من theme النماذج جعلت عنوان الـhero داكنًا على الصورة؛ عُزل لون المشهد وعاد العنوان والنص والأزرار إلى الورقي، مع تقوية سطح الملاحظة الزجاجية الداكن.
2. بعض عناوين الفصول فقدت وزنها عند إزالة globals القديم؛ ثُبت الوزن المقصود دون استيراد قواعد التصميم المرفوض.
3. زر مفضلة بطاقة المنتج كان يستخدم نبرة بيضاء فوق سطح فاتح؛ تحول إلى النبرة المناسبة للأسطح. عولج تعارض specificity كان يُظهر زر القائمة المحمولة على الديسكتوب، والأهداف الأساسية بقيت 44px على الأقل.
4. axe التقط اختلاف الاسم المنطوق عن النص الزخرفي `CARE.` خلف صورة البطاقة؛ أزيل النص الزخرفي غير الضروري، لا قاعدة التدقيق.
5. `understanding.` تجاوزت عرض صفحة about الإنجليزية عند 320px؛ استُخدم حجم عنوان متدرج مناسب مع fallback للالتفاف، بدل إخفاء overflow العام.
6. صفحة المفضلة كانت بلا h1 أثناء انتظار server action؛ انتقل عنوانها إلى SSR، وبقيت عناوين الحالات فرعية.
7. أزرار retry/recovery القديمة احتفظت بأسماء API الخاصة بها ولكن حصلت على primitives مرئية من النظام الجديد؛ لا يتوقف تنسيقها على CSS محذوف.

فُتحت لقطات رئيسية عربية وإنجليزية، كتالوج وموبايل، ملف منتج، about، تواصل، ودخول. اللقطات النهائية والأدلة في [integrated-evidence](integrated-evidence/). هذه مراجعة تنفيذية وليست بديلًا عن رأي صاحب المشروع.

## 5. حدود الإطلاق والعوائق المتبقية

**أُنجز دمج التصميم؛ لم تُنجز شروط إطلاق تجارة حيّة.**

- المعاينة تعمل بـ`NPF_PREVIEW_MODE=1` و`MOCK_CATALOG_FALLBACK=1`: demo repository معلن، ومحددات المعاينة تمنع اعتبارها شراء/تسجيل/حفظ استفسار ناجحًا. التطبيق نفسه موصول بمعمارية المستودع وServer Actions؛ التشغيل المعروض لا يثبت اتصال Payload/Vendure الإنتاجي.
- لا اختبار end-to-end لطلب مدفوع فعلي، ولا live DB mutations، ولا تسليم SMTP، ولا حساب مسجّل/عناوين/طلبات عميل. `e2e/commerce.spec.ts` لم يُشغّل ضد خدمات غير موجودة ولم يُحذف أو يُستبدل باختبارات شكلية.
- تدقيق تبعيات جديد: **production: 25 finding = 16 high + 7 moderate + 2 low، 0 critical**. مع dev: **30 = 21 high + 7 moderate + 2 low**. هذه نتائج npm لا عدد ثغرات قابلة للاستغلال مثبتة؛ لم تُنفذ اقتراحات downgrade/cross-major آليًا. [ملخص التدقيق](integrated-evidence/dependency-audit.json). بوابة الأمن ليست مغلقة؛ انظر [02-security-and-release-gates](02-security-and-release-gates.md).
- البناء ما زال يصدر تحذير Browserslist/Serwist حول require الديناميكي، والتشغيل يحذر من مجلد static القديم. البناء والخادم نجحا؛ لا أدعي خلو السجل من التحذيرات.
- لم يُختبر Docker فعليًا أو تُجرَ ترقية schema في بيئة إنتاج. لا شهادة نتائج سريرية أو تصنيف تنظيمي جديد.
- لا مزامنة جديدة إلى Linear في هذه المرحلة؛ التطبيق غير مفعّل للمحادثة الحالية. وثيقة Google Docs التاريخية لم تُحدّث؛ المرجع الحالي المحفوظ هو هذا Markdown مع الأدلة، ولا يُفترض أن التحديثات التاريخية تعكس اكتمال الدمج.
- لا commit أو push أو merge أو deploy. كل العمل باقٍ على `arena/2f247beb-npf` مع الإصلاحات السابقة. لا إغلاق لبند التصميم أو افتراض اعتماد بصري نهائي من كلمة «كمل».

## 6. الخطوة التالية العملية

مراجعة صاحب المشروع للموقع المتكامل، ثم معالجة ملاحظاته على الصفحات الفعلية. قبل أي إطلاق عام: حسم تبعيات الإنتاج، تجهيز DB/Vendure والبريد والدفع، تشغيل suite التجارة على بيانات اختبار معزولة، مراجعة schema والخصوصية على بيئة النشر، ثم موافقة إطلاق صريحة. لا تعود المراجعة إلى تسليم نموذج مستقل بدل التطبيق.
