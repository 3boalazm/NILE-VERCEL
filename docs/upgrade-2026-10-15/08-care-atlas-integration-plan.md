# تعميم Care Atlas على التطبيق الفعلي — خطة تنفيذ

> **تحديث التنفيذ:** تم دمج الاتجاه وتشغيل التطبيق والتحقق منه. [التقرير النهائي للدمج والأدلة والحدود](09-care-atlas-integrated-handoff.md): 121 unit، 37 browser، 136 زيارة responsive و28 axe audit دون مخالفات مكتشفة. شروط التجارة الحية والاعتماد البصري النهائي ما زالت مفتوحة.

## التكليف — 2026-10-15

قال المستخدم «كمل» بعد مشاهدة النموذج المستقل. هذا إذن للاستمرار في تنفيذ الاتجاه، وليس شهادة اعتماد نهائي لكل صفحة أو إطلاق إنتاجي. ننتقل من نموذج static على 3100 إلى تطبيق Next الحقيقي على 3000، دون iframe أو redirect للنموذج ودون استبدال وظائف المتجر ببيانات JSON ثابتة.

## خطوات التنفيذ

1. نقل نظام التصميم إلى CSS مستقل ذي namespace، وتنظيف globals من تراكب Clinical Glass/Prismatic Care. إبقاء primitives الإتاحة والحركة الاختيارية والـtheme، وتطبيق IBM Plex Arabic/Arial بدل الخطوط السابقة غير المستخدمة.
2. shell حقيقي: رأس جديد ملائم للرئيسية/الصفحات الداخلية، تنقل وأدوات الحساب/المفضلة/السلة واللغة والثيم، وقائمة موبايل قابلة للكيبورد. footer كامل وروابط قانونية. إلغاء الـbottom bar العائم القديم مع إبقاء جميع وجهاته في القائمة.
3. تحويل الرئيسية إلى Server Components وReact: الصورة والرسالة والـperspective، وأطلس عميل ببيانات repository الحالية لا catalog.json، وثلاثة تبويبات معلومات وروابط حقيقة لتفاصيل المنتج/استفسار سياقي. فلاتر وبحث محلي دون طلبات/قياس بيانات صحية.
4. كتالوج جديد بنفس النظام، مع الحفاظ على GET search/filter/sort وترابط اللغة وغياب JS. بطاقات واضحة بصور العبوات الأصلية، أسعار حسب provenance، مفضلة وإضافة حقيقية محجوبة عند غياب التجارة.
5. صفحة منتج جديدة ذات ملف تحريري وروابط أقسام، gallery حقيقي، composition/usage/evidence/FAQ/downloads وشراء/مفضلة دون تغيير قواعدها. الحفاظ على metadata وJSON-LD الآمن وعدم fake offers.
6. إعادة تكوين about/story/quality/contact من المحتوى القائم والحقائق العامة فقط؛ الصور البشرية التوضيحية ليست إثبات مصنع أو نتيجة علاج، وصور المعارض لا تثبت اعتمادًا تنظيميًا. إبقاء النموذج الحقيقي للتواصل مع سياق منتج متحقق منه، وحالة فشل preview الصريحة.
7. توحيد الألوان والخطوط والمساحات وsurface/buttons في صفحات الحساب/السلة/الدفع/الاستعادة والقانونية؛ لا إعادة اختراع state/session أو معالجة المال.
8. بناء production ومعاينة على 3000، ثم type/lint/unit/e2e وتحقق responsive وaxe بعينات عربية/إنجليزية وديسكتوب/موبايل وثيم. فحص screenshots فعلي، حفظ الأدلة والتقرير النهائي. لا إعادة نسبة اختبارات النموذج أو النسخ المرفوضة إلى التطبيق المتكامل.

## معايير/حدود

- المحتوى SSR مرئي بلا JS/hydration، وروابط بديلة للمجموعات والتفاصيل عند غياب تفاعل الأطلس.
- صور packshots الأصلية محفوظة؛ صور/generated coast من النموذج معلّمة توضيحية لا عميل.
- preview صريح، حساب/شراء/حفظ استفسارات محجوب؛ لا شهادة قبول DB/SMTP/payment من معاينة.
- لا تصنيف طبي أو توصية آلية أو شهادة مريضة أو شركاء جدد أو أسعار من static snapshot.
- لا commit/push/deploy ما لم يطلب المستخدم. لا إغلاق لبند التصميم/الإطلاق من طرف الوكيل.
- نتائج/عوائق التنفيذ توثق في تقرير جديد؛ V1/V2 وتقارير النموذج تبقى تاريخية بحدودها.
