## ١. ما الذي تغيّر فعليًا؟

### التصميم والفلو

- اتجاه **Clinical Glass**: خلفية لؤلؤية، أخضر عميق، زجاج هادئ، ناڤ عائم وصور المنتجات الأصلية، مع دعم العربية/RTL والإنجليزية والوضع الداكن.
- إعادة بناء الصفحة الرئيسية: Hero واضح ← احتياجك أولًا ← منتج تحت الضوء ← المصدر والدليل والنشرات ← تواصل واحد واضح.
- إزالة الحشو الترويجي المتكرر من الرئيسية، وإيقاف ترويج المدونة الفارغة ومسار الأسنان «قريبًا» من مسار الاختيار الأساسي.
- تبسيط الكتالوج إلى بحث وترتيب وفلاتر تحفظ بعضها؛ تغيير اللغة يحافظ على سياق الاكتشاف دون نقل tokens أو روابط تحويل تعسفية.
- تحسين تفاصيل المنتج، التفاف الأزرار والكمية على الشاشات الضيقة، وتصحيح إطار تكبير الصور وإعطاء أولوية تحميل لأول صورة فقط.
- تمرير المنتج إلى التواصل عبر slug مُتحقَّق منه، وملء عنوان الاستفسار من بيانات المستودع بدل نص غير موثوق من الرابط.
- رابط تجاوز للمحتوى، focus واضح، حالة ناڤ نشطة، وقوائم موبايل قابلة للإغلاق بـEscape واستعادة التركيز.

### الأمان والاعتمادية

- إصلاح مرحلة Docker المسماة `builder`، واستبدال أسرار build الدائمة بـBuildKit secrets؛ تشغيل runtime دون root وتقليص اعتمادياته.
- تحديث Next/Payload/Vendure/Serwist وتثبيت شجرة متوافقة دون force أو legacy peers، مع patch محدود لـundici.
- فصل مصدر السعر: `live / demo / unavailable`. الإنتاج لا يسترجع سعر mock بصمت عند فشل التجارة؛ أزرار الشراء تتطلب سعرًا حيًا.
- JSON-LD لا ينشر عرضًا تجريبيًا، ولا يخترع المخزون أو الشركة المصنّعة؛ مع escaping آمن لنصوص scripts.
- رفض تغيّر الإجمالي الذي راجعه العميل قبل الانتقال للدفع؛ وتحسين تحقق مدخلات الطلب.
- Service Worker لا يخزّن HTML/RSC أو الحساب/السلة/الدفع. يمسح كاش الصفحات القديم، ويعرض offline محايدًا. تقليل precache من **١٨٦ إلى ٨ عناصر** في القياس المحلي، بدل تحميل جميع الصور والنشرات وحزم الإدارة مسبقًا.
- معالجة رفض تحميل المفضلة، وحدود ٥٠ slug والتحقق منها، وتزامن التخزين بين التبويبات.
- التحقق من نتيجة حذف العنوان والتعامل مع فشل الشبكة في الفورم وأزرار الإضافة بدل pending دائم أو نجاح مضلل.
- فصل تعطل خدمة الحساب عن الحساب الفارغ/انتهاء الجلسة؛ error boundaries محلية وعامة قابلة لإعادة المحاولة.
- rate limiter بذاكرة محدودة وتنظيف دوري، وثقة proxy صريحة بدل أول X-Forwarded-For قابل للتزوير.
- إضافة مسار استعادة كلمة المرور وتهيئة SMTP حقيقية مشروطة؛ **الاستعادة غير مفعّلة افتراضيًا** وتقول ذلك بوضوح حتى اجتياز اختبار التسليم الفعلي.

تفاصيل المصدر والحدود: [01-design-system.md](01-design-system.md)، [02-security-and-release-gates.md](02-security-and-release-gates.md).

### استثناءات مهمة من الأرقام

- اختبار نجاح إرسال نموذج التواصل الأصلي **مستبعد صراحة من تشغيل المعاينة**؛ الوضع يمنع الحفظ، ولا يجوز تزوير نجاحه لتجميل نتيجة الاختبارات.
- اختبارات التجارة الحية `commerce.spec.ts` لم تُستخدم لإثبات شراء/مخزون/SMTP. بيانات الاستجابة المبرمجة في unit tests ليست backend حقيقيًا.
- لم يتوفر Docker daemon أو Postgres/Vendure صالحان لاختبار قبول كامل؛ لا أدّعي نجاح صورة الحاوية أو DB bootstrap أو تدفق الدفع الفعلي.
- البناء يحتوي تحذير bundler من `browserslist` عبر Serwist بخصوص dynamic require. البناء نجح، لكن التحذير محفوظ ولم يُخفَ. هذا ليس تصنيف ثغرة npm حرجة.
- أصلحت أثناء التحقق: اسم اللوجو المقروء، هدفَي لمس أقل من 44px، وعقد الأرقام المرئية مع JS معطل. أُعيدت الاختبارات بعد الإصلاح، ولم تُحتسب النتائج الفاشلة كنجاح.

## ٤. التشغيل وإعادة الاختبار

```bash
npm ci
npm run lint
npx tsc --noEmit
npm test
```

إعداد الإنتاج الحقيقي: اتبع `.env.example`، جهّز Payload/Postgres المزروع وVendure، **اترك علمَي preview/mock مغلقين**، ثم ابنِ وشغّل. ملاحظة: sitemap/catalog يحتاجان قاعدة محتوى متاحة أثناء البناء الحقيقي.

للمعاينة المعزولة فقط، مع قيم بيئة محلية غير إنتاجية لـ`DATABASE_URI` و`PAYLOAD_SECRET`:

```bash
NPF_PREVIEW_MODE=1 MOCK_CATALOG_FALLBACK=1 npm run build
NPF_PREVIEW_MODE=1 MOCK_CATALOG_FALLBACK=1 npm run start -- --hostname 0.0.0.0
```

بعد تثبيت Chromium عبر Playwright، اختبارات المعاينة دون عمليات إرسال حقيقية:

```bash
NPF_PREVIEW_MODE=1 PLAYWRIGHT_BASE_URL=http://localhost:3000 \
  npx playwright test smoke.spec.ts visibility.spec.ts discovery-recovery.spec.ts \
  --grep-invert 'contact form submits'
```

في بيئة الإنتاج التجريبية ذات قاعدة بيانات منفصلة: شغّل اختبار التواصل المستبعد واختبارات التجارة كاملة، ولا توجّهها لبيانات العملاء أو بريد حقيقي دون خطة اختبار.

## ٥. المتبقي قبل الإطلاق

1. قبول الشكل والتجربة ومراجعة المحتوى الطبي/القانوني بشريًا.
2. اختبارات حية لشحن/أسعار/مخزون/حساب/طلب وتأكيد ملكيته، خصوصًا مشكلة Vendure DB-init/placeOrder المبلّغ عنها سابقًا.
3. اختبار SMTP والتسليم الفعلي وexpiry/replay/reset/session invalidation، ثم تمكين الاستعادة. التحقق من البريد الإلكتروني نفسه ليس مسارًا مكتملًا بعد.
4. بناء وتشغيل Docker فعليًا مع الأسرار والمجلدات الدائمة، وفحص history وruntime production-only.
5. معالجة/قبول الثغرات المتبقية، shared/edge rate limiter وثقة proxy الصحيحة. CSP الحالي report-only لا يُوصف كسياسة enforced.
6. اختبار أجهزة وقارئات شاشة وقياسات أداء فعلية؛ لا توجد نتيجة Lighthouse أو Core Web Vitals إنتاجية مزعومة هنا.
