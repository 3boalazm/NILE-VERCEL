# جولة قابلية الاستخدام — البحث والفلاتر وقراءة ملف المنتج

## الطلب — 2026-10-15
استمرار التحسين على الاتجاه الذي أعجب المستخدم، دون إعادة تغيير الهوية أو صورة الحجاب أو صور الصفحات أو الهيدر بالرمز وحده.

## نتائج فحص المصدر قبل التنفيذ
- البحث الحالي يعتمد على substring حرفي؛ التشكيل والتطويل واختلاف الهمزة والشرطات قد يمنع نتيجة موجودة، والبحث في الأطلس يختلف عن الكتالوج.
- الفلاتر الحالية تعمل بـGET دون JS، لكن لا توجد شرائح واضحة لكل فلتر مطبق لإزالته منفردًا مع الحفاظ على بقية السياق.
- الحالة الفارغة فقرة عامة فقط؛ تحتاج تفسيرًا وخطوة استعادة واضحة، لا منتجات أو توصيات طبية مختلقة.
- فهرس ملف المنتج روابط صحيحة، لكنه لا يبين فصل القراءة الحالي، والموبايل يحتاج فهرسًا أبسط دون تغطية المحتوى.
- عادت البيئة دون node_modules أو خادم نشط؛ يلزم استعادة البناء والمعاينة قبل التسليم.

## الخطة
1. مساعد بحث نقي مشترك للكتالوج والأطلس: تطبيع Unicode والتشكيل والتطويل والهمزات والأرقام والشرطات، ومطابقة كلمات البحث دون الاعتماد على ترتيبها. لا توصية علاجية ولا قياس أو إرسال بحث إلى طرف ثالث.
2. شرائح فلاتر SSR وإزالة منفردة مع بقاء q/category/need/sort المسموح بها، والتحقق من category بدل إبقاء قيمة مجهولة كفلتر كاذب.
3. حالة نتائج فارغة مفيدة: سياق البحث، تعليمات مختصرة، رابط إزالة القيود ورابط تواصل عام دون تضمين نص بحث قد يكون حساسًا في نموذج التواصل.
4. فهرس قراءة محسّن: نفس الروابط الأصلية مع active chapter عند التمرير، ونسخة أفقية ملائمة للهاتف. لا progress percentage طبي ولا تغيير محتوى المنتج أو الشراء. بدون JS تبقى كل الروابط صالحة.
5. اختبارات helper والوصول/الفلاتر/no-JS/scroll، ثم build/lint/types/unit/browser وresponsive/axe. أدلة محدودة الحجم، لا تكرار عشرات الصور التاريخية.

## ماذا تغيّر ولماذا؟

### 1. بحث واحد متسامح مع الكتابة
- مساعد نقي مشترك في `src/lib/products/catalog-discovery.ts` يستخدمه الكتالوج والأطلس، بدل منطقين مختلفين.
- تطبيع Unicode/NFKD، إزالة علامات التشكيل والتطويل، تسوية أشكال الألف والياء المقصورة، وتحويل الأرقام العربية والفارسية. الشرطات والرموز فواصل، وحالة الأحرف الإنجليزية لا تغيّر النتيجة.
- كل كلمات البحث يجب أن توجد في اسم المنتج أو اسمه العربي أو وصفه المختصر، دون اشتراط ترتيبها. قد يظهر منتج يذكر الكلمة في وصفه؛ ليس هذا تصحيح أسماء آليًا أو تشابهًا علاجيًا أو توصية شخصية.
- احتُفظ بحد 200 حرف، وبالبحث GET على الخادم. البحث في الكتالوج يظل ظاهرًا في العنوان وسجل المتصفح كالسابق؛ لا ادعاء بأنه قناة سرية أو خالٍ من سجلات الخادم.

### 2. فلاتر مفهومة وقابلة للإزالة منفردة
- شرائح واضحة للبحث والتصنيف والاحتياج والترتيب التنازلي، مع أسماء وصول توضح الإجراء والقيمة.
- كل شريحة رابط SSR أصلي؛ إزالة شريحة لا تسقط بقية السياق الصحيح، ولا تحتاج JavaScript.
- تصنيف غير موجود لا يعود فلترًا وهميًا؛ يُتجاهل في النتائج والروابط التالية. لا إعادة توجيه قسرية لمجرد تنظيف عنوان المستخدم.
- فصل عدد الكتالوج الكامل عن عدد النتائج الحالية لتوضيح الفرق.

### 3. نتيجة صفر ليست طريقًا مسدودًا
- الكتالوج يشرح أن الاختيارات لم تُرجع منتجات، ويعرض البحث كبيانات نصية، مع إرشاد قصير وروابط للكتالوج الكامل والتواصل.
- رابط التواصل **عام بلا نص البحث أو استنتاج طبي**. لا نقل تلقائي لاستعلام قد يكون حساسًا إلى نموذج الاستفسار.
- الأطلس يتيح مسح البحث أو إعادة جميع المنتجات، ويعيد التركيز إلى حقل البحث بعد الإجراء حتى لا يفقد مستخدم الكيبورد موضعه.
- أثناء المراجعة البصرية أُزيل العمود الفارغ المخصص للمنتج عند انعدام النتائج؛ صارت الرسالة تستخدم عرض مساحة العمل بدل فراغ كبير بلا وظيفة.
- اختُبر استعلام متصل بطول 200 حرف، ليُلف داخل الشريحة والرسالة دون كسر عرض الهاتف.

### 4. ملف المنتج أسهل أثناء القراءة
- استخراج الفهرس إلى `DossierNav` مع الإبقاء على روابط الأقسام الأصلية ومحتواها على الخادم.
- تحديد الفصل الحالي بـ`aria-current="location"` من موضع التمرير الفعلي، لا بمجرد آخر نقرة؛ التحديث محدود بـrequestAnimationFrame مع مستمع scroll passive وتنظيف كامل عند المغادرة.
- على الهاتف/التابلت حتى 900px فهرس أفقي ثابت أثناء القراءة، وروابط لا تقل عن 44px ارتفاعًا؛ margin مناسب يمنع تغطية عنوان الفصل.
- يبقى الرابط الحالي ظاهرًا أفقيًا أثناء القراءة العادية، بالعربية والإنجليزية، دون تحريك الصفحة عموديًا أو نقل التركيز أو تشغيل حركة إضافية.
- دون JavaScript تعمل الروابط الأصلية؛ تمييز الفصل تحسين إضافي، وليس شرطًا لقراءة الملف. لا مقياس «تقدم طبي» أو تغيير للجرعات أو الادعاءات أو المراجع أو ملفات PDF.

```bash

npx playwright test e2e/editorial-imagery.spec.ts e2e/motion-polish.spec.ts e2e/smoke.spec.ts e2e/care-atlas.spec.ts e2e/discovery-recovery.spec.ts e2e/visibility.spec.ts e2e/discovery-polish.spec.ts

CARE_ATLAS_SCREENSHOTS=0 node scripts/validate-integrated-care-atlas.mjs
node scripts/validate-discovery-polish.mjs
```

في البيئة المقيدة استُخدم Chromium المؤقت `/tmp/chromium` و`LD_LIBRARY_PATH=/tmp/al2023/lib` مع `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH`. لا تبعية تشغيل جديدة ولا تعديل لحزم الإنتاج بسبب أدوات المتصفح المؤقتة.

## حدود التسليم
- لا تغيير للصور الأربع أو صورة الزوجين بالحجاب الكامل أو صور العبوات الحقيقية أو العلامة الأصلية وحدها في الهيدر.
- لا تعديل لتدفقات المال والحسابات ولا معاملات إنتاجية أو بريد حي. المعاينة demo والبوابات الأمنية السابقة تظل قائمة؛ لا تدقيق تبعيات جديد أو إعلان جاهزية إنتاجية.
- لم تُضف شاشات loading شكلية بلا مشكلة فعلية؛ حالات التحميل والخطأ الموجودة للمفضلة وغيرها احتُفظ بها.
- لا commit/push/deploy أو مزامنة Google Docs/Linear جديدة. العمل محفوظ على `arena/2f247beb-npf`، مع الخطة والتحليل والنتائج محليًا Markdown.
